## Nvisy

The client class. All services are exposed as lazily-constructed properties.

```typescript
import { Nvisy } from "@nvisy/sdk";

const client = new Nvisy({ apiToken: process.env.NVISY_API_TOKEN! });
```

The constructor takes a single `NvisyOptions` object.

### NvisyOptions

| Property | Type | Required | Default | Description |
|----------|------|----------|---------|-------------|
| `apiToken` | `string` | One of `apiToken` / `session` | — | Sent as `Authorization: Bearer <token>` |
| `session` | `true` | One of `apiToken` / `session` | — | Use the browser cookie session instead |
| `baseUrl` | `string` | No | `https://api.nvisy.com` | Custom API base URL |
| `userAgent` | `string` | No | `@nvisy/sdk v.<version>` | Custom user agent |
| `withLogging` | `boolean` | No | `false` | Enable debug logging |
| `headers` | `Record<string, string>` | No | — | Extra headers on every request |
| `credentials` | `RequestCredentials` | No | — | Forwarded to `fetch`; session auth defaults it to `"include"` |
| `fetch` | `typeof fetch` | No | global `fetch` | Custom transport (e.g. a desktop app's native HTTP) |

`apiToken` and `session` are mutually exclusive in the type. `DEFAULTS` and
`VERSION` are exported for reference.

### Instance members

```typescript
client.baseUrl                       // string — the resolved base URL
client.api                           // ApiClient — the typed openapi-fetch client
client.withApiToken(apiToken: string) // Nvisy — a new client with a different token
```

`withApiToken` returns a new instance and leaves the original untouched; all
other configuration is preserved.

### Services

| Property | Description |
|----------|-------------|
| `account` | The authenticated account, public profiles, avatars, sign-in identities |
| `activities` | Workspace activity log and its export |
| `analytics` | Workspace analytics and detection time series |
| `apiTokens` | Create, update, and revoke API tokens |
| `auth` | Logout and desktop-token minting |
| `capabilities` | Labels, recognizers, connectors, and auth methods |
| `connections` | External data source connections, OAuth, import/export |
| `detections` | Detections, their analysis, events, and redactions |
| `documents` | Upload, list, download, update, delete documents |
| `invites` | Workspace invitations and invite codes |
| `members` | Workspace membership |
| `notifications` | Account notifications and the unread stream |
| `pipelines` | Pipeline definitions |
| `policies` | Detection and redaction policies |
| `providers` | Workspace inference providers |
| `redactions` | A redaction's review audit |
| `reviews` | Document reviews, comments, assignees, timeline |
| `status` | Health and readiness checks |
| `syncs` | Connection sync jobs |
| `webhooks` | Webhook endpoints |
| `workspaces` | Workspace CRUD, avatars, notification settings |
| `api` | Underlying typed HTTP client |

<Note>
  Most methods take `workspaceId` as their first argument. Workspaces are the
  top-level tenancy boundary.
</Note>

## NvisyGuest

The pre-auth client, for the endpoints that work without a token: sign-in,
the deployment's auth capabilities, and health checks.

```typescript
import { NvisyGuest } from "@nvisy/sdk/guest";

const guest = new NvisyGuest({ baseUrl: "https://api.nvisy.com" });
```

It takes `NvisyGuestOptions` — the same transport options as `NvisyOptions`
minus the two authentication fields — and exposes three services:

```typescript
guest.auth.loginAccount(credentials: Login): Promise<void>
guest.auth.signupAccount(credentials: Signup): Promise<void>
guest.auth.startOidcSignIn(provider: IdentityProvider, query?: { redirectUri?: string }): Promise<OidcStartResponse>

guest.capabilities.getAuthCapabilities(): Promise<AuthCapabilities>

guest.health.checkHealth(): Promise<Health>
guest.health.checkLiveness(): Promise<Response>
guest.health.checkReadiness(): Promise<Health>
```

<Note>
  `loginAccount` and `signupAccount` set HttpOnly session and CSRF cookies and
  return no body. Construct `new Nvisy({ session: true })` afterwards to use the
  authenticated surface with that session.
</Note>

`uploadDocuments` accepts a single `Blob` or an array, and sends them as

  <Expandable title="properties">
    <ResponseField name="id" type="string" required>Unique document identifier.</ResponseField>
    <ResponseField name="displayName" type="string" required>Display name.</ResponseField>

`ListWorkspaceDocuments` filters by `search` (case-insensitive partial name),
`formats`, `modality`, and `hash` — the last lets you check whether identical
content already exists before uploading it.

`deleteDocuments` is idempotent: it returns `deleted` for the ids that were
removed and `skipped` for ids that were unknown, already deleted, in another
workspace, or held by an in-progress detection.

## Detections

A detection is one analysis pass of a document. It produces findings for review;
applying them is a separate, repeatable step that creates a redaction.

```typescript
listDetections(workspaceId: string, query?: CursorPagination & WorkspaceDetectionsQuery): Promise<WorkspaceDetectionPage>
listPipelineDetections(workspaceId: string, pipelineId: string, query?: CursorPagination & WorkspacePipelineDetectionsQuery): Promise<WorkspaceDetectionPage>
createDetection(workspaceId: string, pipelineId: string, detection: CreateWorkspaceDetection): Promise<WorkspaceDetection>
createAdhocDetection(workspaceId: string, detection: CreateAdhocWorkspaceDetection): Promise<WorkspaceDetection>
getDetection(workspaceId: string, detectionId: string): Promise<WorkspaceDetection>
getAnalysis(workspaceId: string, detectionId: string): Promise<Audit>
getIntermediates(workspaceId: string, detectionId: string): Promise<ArtifactSet>
downloadAudit(workspaceId: string, detectionId: string, query?: ExportQuery): Promise<Response>
events(workspaceId: string, detectionId: string): Promise<Response>
streamEvents(workspaceId: string, detectionId: string): AsyncGenerator<DetectionStatusEvent>
listRedactions(workspaceId: string, detectionId: string, query?: CursorPagination): Promise<WorkspaceRedactionResultPage>
createRedaction(workspaceId: string, detectionId: string, redaction: RedactWorkspaceDetection): Promise<WorkspaceRedactionResult>
```

`createDetection` starts analysis over a single document:

```typescript
const detection = await client.detections.createDetection(workspaceId, pipelineId, {
  documentId: document.id,
});
```

<ParamField path="documentId" type="string" required>
  The document to analyze.
</ParamField>

<ParamField path="scope" type="DocumentContext">
  Per-document languages, jurisdictions, and document labels. Overrides the
  pipeline's `defaultScope` when present.
</ParamField>

`createAdhocDetection` names policies directly instead of going through a
pipeline; it requires `documentId` and a non-empty `policyIds` array, and also
accepts `scope` and `retentionOverride`.

### Detection status

| Status | Meaning |
|--------|---------|
| `pending` | Enqueued; no worker has picked it up yet |
| `executing` | A worker is actively analyzing the document |
| `complete` | Analysis done; the detection is ready to redact |
| `failed` | Detection failed; `error` holds the reason |

A `WorkspaceDetection` carries `id`, `inputDocumentId`, `inputDocumentName`,
`pipelineId` (absent for an ad-hoc detection), `status`, `triggerType`,
`triggeredBy`, `metadata`, `startedAt`, and `completedAt`.

<Note>
  Redaction does not change a detection's status. Each `createRedaction` call
  produces a new `WorkspaceRedactionResult`, whose `outputDocumentId` points at
  the redacted document.
</Note>

### Streaming status

`streamEvents` parses the server-sent event stream into typed
`DetectionStatusEvent` values (`{ detectionId, status }`). It yields the current
status immediately, then each transition, and ends once the detection settles.
Break out of the loop to close the stream early.

```typescript
for await (const event of client.detections.streamEvents(workspaceId, detectionId)) {
  console.log(event.detectionId, event.status);
}
```

`events` returns the raw `Response` if you would rather handle the
`text/event-stream` body yourself.

### Audit and intermediates

`getAnalysis` returns the `Audit` — `report`, `context`, `codec`, `usage`, and
an optional `recognition`. `downloadAudit` returns it as a file: `csv` by
default (a zip of `entities.csv`, `provenance.csv`, and `reviews.csv`), or
`json` with `{ format: "json" }`.

`getIntermediates` returns an `ArtifactSet` of modality-tagged parts — an
image's OCR layout, an audio clip's transcript, or tokenized text. A detection
whose analysis ran no enricher has none and responds 404.

### Verifying deliveries

The `@nvisy/sdk/webhooks` entry point verifies an incoming delivery and parses
it into a typed event, using Web Crypto so it runs in Node, browsers, edge
runtimes, and workers.

```typescript
import { constructEventFromRequest } from "@nvisy/sdk/webhooks";

const delivery = await constructEventFromRequest(request, {
  secret: process.env.NVISY_WEBHOOK_SECRET!,
});

// delivery.event, delivery.requestId, delivery.timestamp, delivery.payload
```

For runtimes without a Fetch `Request`, `constructEvent` takes the raw body and
headers directly; `WEBHOOK_HEADERS` names the four headers a delivery carries
(`X-Webhook-Signature`, `X-Webhook-Timestamp`, `X-Webhook-Event`,
`X-Webhook-Request-Id`). Verification failures throw `WebhookSignatureError`.

<Warning>
  Pass the **raw** request body, not a re-serialized one — re-encoding JSON
  changes the bytes the signature was computed over.
</Warning>

## Date Windows

Methods taking a `DateWindow` accept an inclusive `from`/`to` day range as
`YYYY-MM-DD` strings. Both are optional: `to` defaults to today (UTC), and
`from` defaults to a fixed window back from `to`.

```typescript
const series = await client.analytics.getDetectionTimeSeries(workspaceId, {
  from: "2026-01-01",
  to: "2026-01-31",
});
```

## Pagination

List methods are cursor-paginated and accept `CursorPagination`:

| Property | Type | Description |
|----------|------|-------------|
| `after` | `string` | Cursor pointing at the last item of the previous page |
| `limit` | `number` | Maximum items to return (1–100, default 20) |
| `includeCount` | `boolean` | Populate the response's `total`; defaults to `false` since counting costs an extra query |

Every page has `items`, an optional `nextCursor`, and an optional `total`.

```typescript
let after: string | undefined;
do {
  const page = await client.documents.listDocuments(workspaceId, { after, limit: 50 });
  for (const document of page.items) console.log(document.id);
  after = page.nextCursor;
} while (after);
```

## Errors

```typescript
import { NvisyError, NvisyApiError } from "@nvisy/sdk";
```

`NvisyError` is the base class, thrown for SDK-level problems such as an
invalid API token. `NvisyApiError` extends it for API responses:

| Property | Type | Description |
|----------|------|-------------|
| `name` | `string` | Error type identifier (e.g. `ValidationError`, `NotFoundError`) |
| `message` | `string` | Human-readable message safe to display |
| `statusCode` | `number` | HTTP status code |

Helpers: `isClientError()` (4xx), `isServerError()` (5xx), `isRetryable()`
(5xx, 408, or 429), and `toJSON()`.

```typescript
try {
  await client.detections.createRedaction(workspaceId, detectionId, {});
} catch (error) {
  if (error instanceof NvisyApiError) {
    if (error.isRetryable()) {
      // Retryable transport/server error. Retrying `createRedaction` is not
      // automatically safe — each call produces a new redaction, so re-read
      // the detection's redactions before trying again.
    }
    console.error(error.statusCode, error.name, error.message);
  }
}
```

<Warning>
  `isRetryable()` reports that the *error* is of a transient kind, not that the
  *operation* is safe to repeat. Retry automatically only for reads.
</Warning>
