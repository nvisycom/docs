The Nvisy API is a REST API over HTTPS. It accepts and returns JSON, except
where file content is uploaded or downloaded.

<Info>
  The endpoint reference in this section is generated directly from the
  server's OpenAPI specification, so it always reflects the deployed API.
</Info>

## Base URL

```
https://api.nvisy.com
```

Self-hosted deployments serve the same API from their own host. A local
development server defaults to `http://127.0.0.1:8080`.

## Authentication

All requests authenticate with a bearer token:

```bash
curl https://api.nvisy.com/workspaces/ \
  -H "Authorization: Bearer $NVISY_API_TOKEN"
```

Create tokens under **API Tokens** in your account settings, or through the
`/api-tokens/` endpoints.

<Warning>
  A token's secret is returned only once, at creation. Store it securely — it
  cannot be retrieved afterwards.
</Warning>

## Workspaces

Nearly every resource lives inside a workspace, addressed by its slug:

```
/workspaces/{workspaceSlug}/files/
/workspaces/{workspaceSlug}/pipelines/
/workspaces/{workspaceSlug}/runs/{runId}/
```

Workspaces are the tenancy and access-control boundary. List yours with
`GET /workspaces/`.

## The Redaction Workflow

Redaction happens in two phases, so findings can be reviewed before anything is
modified.

<Steps>
  <Step title="Upload a file">
    `POST /workspaces/{workspaceSlug}/files/` — multipart upload, returns file
    metadata including the file ID.
  </Step>
  <Step title="Start a run">
    `POST /workspaces/{workspaceSlug}/pipelines/{pipelineSlug}/runs/` with a
    `fileId`. The run analyzes the document against the pipeline's policy.
  </Step>
  <Step title="Review detections">
    `GET /workspaces/{workspaceSlug}/runs/{runId}/detections/` returns the
    audit of what was found.
  </Step>
  <Step title="Apply redactions">
    `POST /workspaces/{workspaceSlug}/runs/{runId}/redactions/` produces the
    redacted output file.
  </Step>
</Steps>

### Run Status

| Status | Meaning |
|--------|---------|
| `queued` | Enqueued for detection; no worker has started |
| `analyzing` | A worker is actively analyzing the document |
| `analyzed` | Detection finished; awaiting review |
| `completed` | Redaction applied; run finished |
| `failed` | Run failed — see the `error` field |
| `cancelled` | Cancelled by a user |

Poll `GET /workspaces/{workspaceSlug}/runs/{runId}/` or subscribe to
`GET /workspaces/{workspaceSlug}/runs/{runId}/events` for a server-sent events
stream.

## Pipelines and Policies

A **policy** defines what counts as sensitive. A **pipeline** defines how a
document is processed and which policy applies. Both are workspace resources
and are reused across runs.

Browse the available detection labels and recognizers through
`GET /catalog/labels/` and `GET /catalog/recognizers/`.

## Pagination

List endpoints are cursor-paginated:

| Parameter | Description |
|-----------|-------------|
| `limit` | Maximum items to return |
| `after` | Cursor pointing at the last item of the previous page |

Responses contain `items`, `nextCursor`, and `total`. Continue while
`nextCursor` is present.

## Errors

Errors return a JSON body alongside the HTTP status code:

```json
{
  "name": "NotFound",
  "message": "Workspace not found",
  "resource": "workspace",
  "suggestion": "Verify the workspace slug"
}
```

| Status | Meaning |
|--------|---------|
| `400` | Malformed request or failed validation |
| `401` | Missing or invalid token |
| `403` | Authenticated, but not permitted |
| `404` | Resource does not exist |
| `429` | Rate limit exceeded |
| `5xx` | Server error — safe to retry with backoff |

## Audit Export

Every run's audit can be exported for long-term archiving:

```
GET /workspaces/{workspaceSlug}/runs/{runId}/audit/json
GET /workspaces/{workspaceSlug}/runs/{runId}/audit/csv
```

## Webhooks

Register endpoints under `/workspaces/{workspaceSlug}/webhooks/` to receive
events as runs progress. Use the `test` endpoint to verify delivery before
relying on it.
